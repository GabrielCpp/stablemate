# Run Activity tab

The Activity tab answers one question about a run: what did each agent turn say and do. The Overview shows where the time and money went. It does not show the words of a turn. The Activity tab lists the run's agent turns, and the steps, gates, retries and churn alerts around them, under the work item and flow pass they happened in. The operator can also put the run's INFO logs among the rows, open every fold of passed steps, or switch to the Raw view, which lists every stored record of the run newest first. The operator opens a turn to read its prompt, its thinking, its messages and its tool calls, with the long parts folded away until asked for, or a step or a gate to read its error, its logs, its question and answer and what came next, or a retry or a churn alert to read its name, time and one-line result, beside the list.

The tab follows Overview in the [detail tab bar](../gui/screens/groom-dashboard.md#detail-tabs) and is there for every run, native or container, with or without a sidecar. A turn's figures come from the run's stored spans through [get-run-activity](../http/get-run-activity.md), and a turn's words come from its stored record or, while it runs, from the run's live transcript, through [get-run-turn](../http/get-run-turn.md). A step's or a gate's details come from the run's stored spans and logs, its live telemetry and its gate file, through [get-run-entry](../http/get-run-entry.md). The Raw view pages through the run's stored records through [get-run-records](../http/get-run-records.md). The browser holds one list, the fold state of its headings, one open row and, in Raw, one list of records.

Transcript text is untrusted. A model or a tool can write any characters, so no part of a turn reaches the page as markup the server or the browser did not choose.

- extends: [run flow tree](run-flow-tree.md)
- rule: the list groups its rows under a work item heading, then a flow pass heading, and one row is one visit. A node that runs twice has two rows. A run with no work item reads as one unnamed item whose heading is left out, so the flow pass headings stand directly in the list. Work done outside any work item is the first group, headed `Outside any work item`, and work outside any flow is a pass headed `outside any flow`.
- rule: one row is one visit, the turns of one slug under one parent span, so a retry inside a visit stays one row. A slug that a resumed pass repeats gives one row per visit, each under its own heading and each with its own start, time, cost and pass, so the rows of a pass add up to its heading. The first visit keeps the plain slug as its key. A later visit's key adds `~` and the millisecond its own turns began, which does not change when the list is read again. A row reads only the records of its own visit. When the archive kept none for it, the pane says no record of the turn could be found and offers no retry.
- rule: a pass number counts from one within one work item and one flow, in the order the pass headings are shown, so the headings of a work item read `dev · 1st pass`, `dev · 2nd pass`, `dev · 3rd pass` with no gap and none out of order. A run with no work item counts within the flow across the run. The pane head of a turn shows the number of the heading the turn sits under.
- rule: a work item heading carries its state, active time and cost from the same figures as the Overview's work item table, so the two agree. A flow pass heading carries its state, time and cost from the flow tree's leaf rule, with the time of its state steps added, so the passes of one flow add up to that flow's row in the Overview.
- rule: a work item's state reads `running` while its turn runs, `in progress` for the newest item of a live run, then `done`, `not counted` or `count unknown` from the Overview's outcome. A flow pass reads `running`, `open`, `failed` or `passed`.
- rule: a heading is a button that opens and closes its rows, with `aria-expanded` and an accessible name that says its state, time and cost in words. A finished work item or flow pass starts folded. The item and the pass in progress start open. The group holding the selected row is open whatever the fold state. A choice the operator made on a heading holds across reads.
- rule: a step is a node span that holds no node or state, or a state span that holds no child span except infra spans. A state whose body does its own work records only its state span, so that span is the step. A state that holds a node, a nested state, an agent turn or a wait is not a step, because those children already show. Start, route and finish states count like any other, with no list of names. The row shows the node name without the `state:` prefix. It folds with its neighbours, opens under `Steps`, reads like any other step, sits in the work item and flow pass of its flow, and is reached by search, `j` and `k`. A state that failed stands alone as a failed row and is counted once with the other problems. The time of a state step counts in its flow pass heading, failed ones included, so the passes of one flow add up to that flow's row in the Overview. The work item heading stays the agent turns only, as the Overview's work item column does, and its tooltip says so. A state step carries no cost.
- rule: a run of successful steps folds to one row that says the count, the time and `all passed`. Selecting the row opens it into one row per step, and selecting it again closes it. A failed step, a gate, a backend retry and a churn alert each stand as their own row between the folds, and each has a mark of its own, a cross, a question mark or an exclamation mark, so the kind never rests on color alone.
- rule: the bar has a `Problems` control that shows the count of problems and exposes whether it is pressed. Pressing it narrows the timeline to the problems, under their work item and flow pass headings, with every heading open and every heading that holds no problem left out. Pressing it again restores the whole timeline. The control is a button with a name, and the keyboard operates it like any button.
- rule: every count of problems reads one definition: the failed steps, the backend retries, the failed gate checks and the churn alerts of the run's stored spans. The Problems control, the tab badge, the Overview attention tile and the rows of the Problems view all come from it, so the number of rows in the view equals the count. A failed turn and a failed container step are failed steps. A gate check that is dirty and errored counts once. An answered gate is not a problem, is not in the view and adds nothing to the count.
- rule: a failed agent turn shows once in the whole timeline, as its turn row marked failed, and that row is a stop for `e`. The Problems view lists it as a failed row and selecting that row offers `Open that turn`, so the rows of the view still equal the count.
- rule: the Problems view opens at its newest row, and leaving it brings the selected row of the whole timeline back into view. The search and the work item filter apply inside the view, and a work item or a query with no problem says so and offers to clear the filters or the search.
- rule: pressing `Problems`, or opening the view from the attention tile, selects the newest row of the view and reads it in the pane when the selected row is not in the view. A selected row that is in the view stays selected, and turning the view off keeps the selection. A row that the search or the work item filter hides inside the view follows the same rule. `Open that turn` shows the turn with no row selected.
- rule: a run with no problem says `This run has no problems.` in the view and offers `Show the whole timeline`, and the pane says what the view lists. The control then reads `Problems 0` and the tab shows no badge.
- rule: the Activity tab shows a badge with the count of problems when it is above zero, and its accessible name says the count in words, as `Activity, 5 problems`. The badge and the Overview attention tile show the same number. The problem count on the tile is a link that opens the Activity tab with the Problems view on.
- rule: selecting a retry or a churn alert opens its reading in the pane in place of a transcript, headed by its name and time. A retry says that the backend started the turn again after the attempt before it ended, adds the failure of that attempt and the seconds the backend waited only when the stored spans record them, and links to its turn with `Open that turn`. It then says that the attempt failed, that it finished and the turn went on, or that the backend started it again, and never says that the retry succeeded. A churn alert says what repeated, the node, how many times in a row and on which work item, that the labels did not change and that the run may be going round in circles, and says what came next with a link to it. Selecting a step, a failed step or a gate opens its full reading instead, and a row that opens one has the same name, time and one-line result in the list as before.
- rule: the row of a churn alert and the head of its pane read `CHURN` in every Activity state, and its accessible name keeps the words `churn alert`.
- rule: a step's reading is its head, its error, its logs and what came next. The head names the step, its work item, its flow pass, its duration and, when it failed, its error class. A failed step shows its whole error text under the label `Error` marked with a cross, so the error never rests on color. The error class shows as a name and the server's error kind is not shown.
- rule: a step's logs are the log lines the run recorded for the step's node inside the step's own window, oldest first, each with its time, its level, its node and its message, up to 500 lines. A line at level `ERROR` or `FATAL` is bold, and a warning is amber. A step with no lines says it recorded none.
- rule: what came next is the row that follows the selected one in the list's time order, and it names that row's kind. The reading offers a button that opens that row in the list, unfolds its groups and scrolls it into view. A step with no row after it says `Nothing came after this.`
- rule: a gate's reading is its question, its answer, when it was answered and how long it waited, and the answer is read from the gate file the wait named, after the place the question stands in it that belongs to that asking, and before the next question. When the same question stands in the file more than once, the nth asking reads the nth place, counting the waits that completed. An asking with no place of its own reads as unanswered and never takes a neighbour's answer, and the pane then says `The gate file holds no answer for this asking.` An older gate finds its own answer above a newer question. A gate file that cannot be read says the answer is not available and never shows an empty answer.
- rule: a gate's key is `gate:<node>#<n>`, where `n` counts the node's operator waits in the order they started, so the key of a gate stays the same while it is open and after it is answered. The pane answered from the box above the tabs keeps the same row selected.
- rule: a step that is running and a gate that is open have no stored span, because a span is stored when it ends. They come from the run's live telemetry as rows of their own, a running step as `step:running:<node>`, in the group last worked in. A running step reads `running` and says nothing has come next, and the key moves to the finished step when the step ends. A run whose telemetry has gone silent shows neither row.
- rule: while a step runs or a gate is open, the pane reads again every 3 seconds, and answering an open gate reads it again at once, so the pane turns answered without a reload and without moving the selection.
- rule: a step or gate that is being read shows `Reading this step…` and clears it when the details arrive. A step that cannot be read says `The details of this step could not be read` with `Retry now`, keeps its row and its one line in the list, and a successful retry replaces the message with the details.
- rule: log lines, error text, questions and answers are untrusted. The page shows them as text, and the question and the answer as formatted prose with raw markup neutralised.
- rule: a backend retry is a repeat turn in one visit, an agent turn that follows an earlier attempt under the same parent, and its row sits where that turn started. Its cause is shown only when recorded, so its text takes the delay the backend waited from the `retry` event the earlier attempt recorded and reads `<node> turn started again` when no event was recorded. A churn alert comes from replaying the churn rule over the run's stored spans, so both come back unchanged after groom restarts and nothing is stored apart from the spans.
- rule: a turn that is running has its own mark and is the last row of its flow pass. Its figures come from the live rows until it ends, and it is placed in the group last worked in.
- rule: a heading stays in view while its rows scroll, the flow pass heading under the work item heading it sits in.
- rule: the tab opens on the newest turn, the last row of the list, and selecting another row opens that one. A list that is read again keeps the open turn when its row is still there, and otherwise opens the newest.
- rule: a turn of a run recorded before spans carried a visit slug takes the slug of the one stored turn record of the same node and session whose time lies within 5 seconds of the span's start and end. When exactly one record fits, the turn reads from that record. When none fits or several fit, the turn gets the stable key `unmatched-<span id>`, its pane says no record of the turn could be found, and the server never retries the match or guesses between records.
- rule: a message renders as Markdown. Raw HTML inside it shows as literal text, an image shows as its alt text and produces no image element, and the result goes through DOMPurify before it is set as markup. A client where the Markdown renderer or the sanitizer did not load shows the message as plain text with its line breaks kept.
- rule: a turn's result is the first line of its recorded `summary`, else of its recorded `notes`, else of the span's activity label, else for a running turn the first line of its last agent message. The row and the pane head show that line and never a line the operator has to open the turn to find.
- rule: a finished turn reads only the entries inside its own window, from 5 seconds before its start to 5 seconds after its end. A session resumed across turns holds earlier turns' lines in the same file, and the window is what keeps them out of this turn.
- rule: a running turn shows only the figures it has. Its head omits the model, the cost, the pass and the output tokens, because none is known before the turn ends. The cost reads `lands at turn end`.
- rule: the live history holds the last 200 updates, so a long running turn can lose its start. A turn read from it whose first update is gone says `Earlier output of this turn is not shown`.
- rule: a turn outside any flow node shows no pass. The head never reads `pass 0` or `0th pass`.
- rule: the tab reads the list once when it opens and again when the run's figures revision moves, again when the dashboard's connection returns after a loss, and while a turn runs it reads the list and the open turn every 3 seconds. A read of a turn that was running when the previous read happened reads the turn again, so the pane shows how it ended. All of them keep the operator's scroll and selection.
- rule: the timeline of a live run follows it. The list keeps its newest row in view as rows arrive, and the tab opens following. When a later group sits below the newest row, the list scrolls to the newest row and not to its foot, so the row is neither past the edge nor under a sticky heading. A run that has ended, or that was over when the tab opened, has no follow control, no pill and no scrolling to the end.
- rule: scrolling the list up by any amount that leaves it more than 4 pixels from its end pauses the follow, and the control then says `Paused`. A scroll that does not move the list up, such as one caused by a row arriving, never pauses it. Scrolling back to within 4 pixels of the end follows again. Pressing the control pauses a following list where it stands and follows a paused one from its newest row.
- rule: a paused list changes nothing under the operator's eyes. The rows in view stay where they are, the scroll position holds, and a heading that was open at the pause stays open until the list follows again, even when the work item or the pass it heads finishes.
- rule: the pill counts the rows that arrived since the pause. In the Problems view it counts only the problems that arrived and reads `N new problems` or `1 new problem`. A turn, a step, a gate, a retry and a churn alert are each one, and a step that folds into a run of passed steps counts as its own row. The row that shows the step a run is in, and a row that was there at the pause, are not counted. Log rows that the operator adds by pressing `Info logs` during the pause are not counted either. The count is the number of keys now in the timeline that were not in it at the pause, so a row that arrives and goes again leaves no count.
- rule: pressing the pill selects the newest row and opens it in the pane, scrolls it into view, clears the pill, follows again and moves focus to the control. The newest row is the one with the latest time among the turns, steps, gates, retries and churn alerts, and a fold that holds it opens. Scrolling back to the end and pressing the follow control follow again and leave the selected row and the pane as the operator left them. While the list follows, a row that arrives never moves the selection.
- rule: a row that arrives never selects itself, never takes focus from what the operator has focused, and never rebuilds an open pane. The pane of the selected turn changes only when the turn it shows is itself still running and its own record moves.
- rule: the follow control says `Not connected`, disabled, while the dashboard's connection is `reconnecting` or `offline`, and says what it did before when the connection returns. A `stale` connection does not change it, because the page still receives frames. The list reads again when the connection returns, so the rows that arrived during the loss appear, and a following list moves to its newest.
- rule: when the run ends while the tab is open, the follow control and the pill go, the search field and the selector stay, and the list stops following. The running row reads as the turn ended, with the figures and the result of the turn's stored span, and the headings and the run's row take that turn's cost. A running turn that ends with the run and leaves no span of its own follows the no-record rule.
- rule: a run that has ended while a turn still has no span of its own marks that turn as ended with no record. Its row reads `ended with no record`, with no running dot and no ticking time. The pane badge reads `NO RECORD` in place of `RUNNING`, the head drops `cost lands at turn end`, and the pane says `This turn ended with no record, so its cost was not reported.` above the transcript already shown. The pass and group headings drop `running`. The headings and the run's row keep the cost they had, and the turn never gets a guessed cost or a cost of 0.
- rule: the flow heading sticks directly under the group heading it belongs to. The list measures the group heading's rendered height and gives the flow heading that value as its sticky offset, so no row shows between the two headings at any scroll position.
- rule: the control, the pill and the arrival count are named for assistive technology. The control is a button whose `aria-pressed` says whether it follows. The pill is a button inside a polite live region that is present while the run is live and empty while no count shows, so the count is announced when it appears and as it changes. Neither relies on color alone.
- rule: a list that fails to read says so with a retry and never reads as empty. A turn that fails to read says so with a retry and keeps the list. A run with no turn says it has no activity yet and whether the run is alive.
- rule: a turn's pane reads, from the top, the prompt, the thinking, then the messages and tool calls in the order they happened. The prompt and the thinking each start collapsed, and the prompt's label carries its size in words, as `Prompt · 3,412 words`. Opening one shows its text and closing it removes the text again.
- rule: the prompt is the turn's recorded `prompt.md`, else the text of the transcript's user messages in the turn's window. The thinking is the turn's thinking blocks joined in order into one part. A turn that has neither says `This backend did not record the prompt or the thinking for this turn.` where they would sit, and names only the missing one when the other exists. A running turn shows no such note, because its prompt and thinking land at turn end, and neither does a turn read from the live history that lost its start.
- rule: three or more tool calls in a row that all succeeded fold to one line that counts them by tool, most used first, and gives their summed time, as `11 Read · 4 Grep · 2 Bash · 1m 12s`. One or two successful calls stay as their own lines. A call with no recorded time adds none to the sum, and a fold with no timed call omits the time. The tool is the first word of the call's name, so a backend that names a call by its whole title still counts by tool.
- rule: the fold is a button with `aria-expanded`. Opening it shows one line per call with the tool, its summary and its time, and closing it folds the lines again. A call's time runs from its call to its result in a Claude transcript, from the first to the last update of its tool call id in an ACP transcript or the live history, and from the recorded start to end in an opencode transcript. A Codex transcript records no tool time, so its calls show none.
- rule: a failed tool call never sits inside a fold. It splits the run of successful calls around it, stands on its own line marked in red and with the words `failed`, shows its time, and shows its output in full in a box of its own. A box taller than about 220 pixels scrolls inside itself and leaves the rest of the turn where it was. The server carries a failed call's output up to 1,000,000 characters and carries none for a call that succeeded.
- rule: the last assistant message of a finished turn is its final output. It is labelled `Output` and set apart from the other messages by a bar down its left edge. A running turn has no final output yet.
- rule: the prompt, the thinking and a tool's output are untrusted text. The prompt and the thinking render as Markdown under the message rule, and a tool's output renders as literal text in a `pre` box that is a named, focusable region, so a script or an image in any of them runs nothing and loads nothing.
- rule: a part's open state belongs to the turn on screen. Selecting another turn, or reading the same one again after another, shows every part collapsed. A read that only refreshes the open turn keeps the parts the operator opened.
- rule: a finished turn of a native run whose record is not on this machine, because no record was archived for it or the record holds no transcript, reads as a turn with no messages, for a plain slug and for a suffixed key alike. The server answers `200`, the pane says no record of the turn could be found, and it offers no retry. Only a turn of a container run whose records are not pulled yet answers `503` with a retry, and a still-running turn with no rows yet is unchanged.
- rule: the tab shows no archived run's turns.
- rule: on the Activity tab, `j` selects the next row and `k` the previous one in the order the rows are on screen, the selected row stays in view, and the pane opens it. On every other tab `j` and `k` keep moving the run list. A key never acts while the operator types in the search field, the gate answer box or any field, and never while the work item selector is focused.
- rule: `e` selects the next problem after the selection and wraps to the first, and it steps through the same rows the Problems view lists. A problem is a failed step, a failed gate check, a backend retry or a churn alert, and a failed turn is a failed step. In the whole timeline a failed turn is a stop once, at its turn row. A heading that folds the problem opens so the row can be reached. With no problem in the run, `e` says `This run has no problems.` and the selection stays.
- rule: after `j`, `k` or `e` moves the selection, focus sits on the selected row when focus was on the page or on another row of the list, so Enter and Space act on the row the operator just moved to and no focus ring shows on another row. A key never takes focus from another control.
- rule: a key that moves to a row outside the list box pauses the follow of a live run before it scrolls, and a key that moves to a row already in view keeps following. A key never turns the follow on, so the control, the pill and the arrival count keep their meaning. The bar labels `j k` as `move` and `e` as `next problem`, for every run.
- rule: the search field narrows the rows at once by the text of the row, and marks the match as text, never as markup. A search opens every heading and unfolds every run of passed steps so a match inside one shows. The work item selector limits the list to one item, its first option shows every item, and it opens no heading. The search and the selector apply together, and clearing both restores the list.
- rule: a search also reads the transcripts of this one run, after a quarter second without typing, and never another run. It matches the messages, the tool summaries and the output of failed tool calls, never the prompt or the thinking, and a turn gives its first matching line, cut to 160 characters. The query is cut to 200 characters. A row found there says `in transcript` with the line.
- rule: while the transcripts are read, a status says `Searching the transcripts of this run…`, and it clears when the search ends. A search with no match says what was searched and offers to clear it. A transcript search that fails reads whole or not at all, says the transcripts could not be searched, keeps the matches of the row text and offers a retry, and a successful retry adds the transcript matches and clears the message.
- rule: the node name in the head of a turn stays on one line, and a long work item name beside it wraps
- rule: the word `Only` labels the `Problems` control in the bar, in the same style as `Also show`.
- rule: the bar has a `Steps` control and an `Info logs` control after the words `Also show`, each with a count and each exposing whether it is pressed. `Steps` counts the passed steps the folds hold, and pressing it opens every fold of passed steps into one row per step. Pressing it again closes them, including a fold the operator opened by hand. It opens step folds only and leaves the work item and flow pass headings as they were.
- rule: `Info logs` counts the log lines at INFO level and above, so a debug line is not a row and the Raw view lists it. Pressing it puts one row per line into the timeline at the place its time falls, and pressing it again takes the rows out. The server places a line in the flow pass whose first turn started latest at or before the line, ordered by time among that pass's entries, so a line before every pass sits in the first pass. A log row never splits a fold of passed steps, because the folds are made before the lines are placed.
- rule: a log row selected reads its level, node, time and message in the pane, as text. The count of the control is the run's count whether the lines are placed or not.
- rule: the `Raw` control replaces the timeline and the pane with a list of the run's stored records, newest first. The records are the spans, one per span written when it ends with its duration and, when priced, its cost, the logs of every level, the turn events and the churn alerts. Each shows its time, its kind, its node and its text, and a failed span and a churn alert read in the failure colour.
- rule: the Raw list has one total order, time then kind then id, and a page continues from a cursor that holds those three. Two records with the same time keep one place across pages, so no record is lost or shown twice. The kinds rank churn alert, span, event, log and metric sample, highest first.
- rule: metric samples stay out of the Raw view until the `Metric samples` control asks for them. The control shows the run's count of samples either way, and the note above the list says how many records the run has, how many metric samples are hidden or included, and how many records are shown.
- rule: the Raw view shows the newest 200 records, and `Load older records` adds the next page below the list without moving the reader. The last page removes the control, and a page that is full with nothing older has no cursor and no control. A page the server returns holds at most 200 records.
- rule: in the Raw view a live run that follows reads again every 3 seconds and puts new records at the top. A paused list holds them, and a run that has ended is read once. Following is the Activity tab's own follow state, so the control keeps its reading across Raw and the timeline.

- rule: the turn pane takes whether a record exists from the turn read (`head.matched`) and not from the timeline row, falling back to the row only when the read carries none.
