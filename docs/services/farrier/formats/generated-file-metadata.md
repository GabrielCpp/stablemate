# Generated-file metadata block

The `metadata:` mapping farrier stamps into every generated skill/command's YAML front matter, via
`skill_metadata_block`. Without it, an agent editing a generated file "fixes" a copy — the edit is
lost on the next `make agent-install`. Skills carry it natively (the openskill format defines
`metadata`); Claude commands carry the same block — the slash-command parser ignores keys it
doesn't recognise, so the block is inert to the consuming agent. [`farrier source`](../farrier-commands-init.md#source)
reads the block back via `frontmatter_metadata` to resolve a generated file to its editable library
origin.

- file: front matter of any farrier-generated `SKILL.md` / command `.md` under `.claude/`,
  `.agents/`, or `.github/`
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e — writes the block
- code: `farrier/farrier/frontmatter.py::frontmatter_metadata` @9cdb7d1662b8 — parses the nested mapping
- code: `farrier/farrier/frontmatter.py::frontmatter_metadata` @9cdb7d1662b8 — implementation moved from the compatibility facade; the CLI imports this parser
- tests: `farrier/tests/test_frontmatter_parsing.py::test_tags_and_metadata_read_the_same_block_as_split`

## Fields

### field: name
- type: `string`
- default: the source's library name
- verify: json_path(path="$.metadata.name", matches="^[a-z0-9-]+$")
- required: true
- semantics: the kebab-cased folder name of the library source, without the install prefix
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e

The library name of the skill or prompt the file came from. It is the key a reference resolves
against, and it is the same on every machine because it carries no repo prefix.

### field: generated_by
- type: `string`
- default: `farrier`
- verify: json_path(path="$.metadata.generated_by", equals="farrier")
- required: true
- semantics: marks the file as generated by farrier and therefore eligible for managed replacement or deletion
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e
- detail: [generated-file metadata fields](../concepts/generated-file-metadata-fields.md)

Always the literal string `farrier`; marks the file as tool-generated rather than hand-authored.

It is also what makes the file *deletable*: install removes only files carrying this mark, so a
hand-written skill kept next to the generated ones survives, and a path farrier wants to write that
holds an unmarked file aborts the install instead of overwriting it. See
[ownership](../farrier-commands-install.md#ownership) — and note that a generated `SKILL.md` covers its bundled
`references/`/`scripts/` too, which carry no front matter of their own.

### field: source
- type: `string`
- default: none
- verify: json_path(path="$.metadata.source", matches="^library/")
- required: true
- semantics: library-anchored POSIX path to the editable source document
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e
- detail: [generated-file metadata fields](../concepts/generated-file-metadata-fields.md)

The generated file's origin within the prompt library, as a **library-anchored, machine-independent
path** — anchored at the last `library/` path segment (e.g. `library/skills/go/go-qa/SKILL.md`), so
the same value is identical across machines and stable under `install --check`. Computed by
`library_source_path`. Joined under the resolved [library directory](../concepts/library-directory.md)
by `farrier source` to print this machine's absolute editable path.

### field: resolve
- type: `string`
- default: none
- verify: json_path(path="$.metadata.resolve", matches="^farrier source ")
- required: true
- semantics: copy-pasteable `farrier source <generated-file>` command for this generated file
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e
- detail: [generated-file metadata fields](../concepts/generated-file-metadata-fields.md)

A copy-pasteable command, `farrier source <dest_rel>`, where `dest_rel` is the generated file's own
repo-root-relative path. Running it prints the real editable source path on the current machine.

### field: do_not_edit
- type: `string`
- default: fixed warning text
- verify: json_path(path="$.metadata.do_not_edit", matches="edit the library source")
- required: true
- semantics: instructs the reader to edit the library source and regenerate rather than edit the generated copy
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e
- detail: [generated-file metadata fields](../concepts/generated-file-metadata-fields.md)

A human-readable warning: run the `resolve` command for this machine's editable source path, edit
that, then `make agent-install` to regenerate this file.

### field: tags
- type: `list<string>`
- default: omitted when the source has no tags
- verify: json_path(path="$.metadata.tags", absent=true)
- required: false
- verify: json_path(path="$.metadata.tags", matches="^\\[\"web\", \"tests\"\\]$")
- semantics: normalized source tags, lowercased, deduplicated, and order-preserving
- code: `farrier/farrier/renderer.py::skill_metadata_block` @e8988703cc7e
- detail: [generated-file metadata fields](../concepts/generated-file-metadata-fields.md)

The library source's own `tags:`, normalized (lowercased, deduplicated, order-preserving) and
emitted as a YAML flow list — `tags: [web, tests]` — only when the source declares any. Tags say
what the skill *answers* rather than what it is called, which is how a workflow prompt asks for a
capability it has no name for; the run-time half of that query is workhorse's
`find_by_tags(*tags)`, reading the same values out of the [context
 manifest](../../workhorse/concepts/run-launch.md#run-launch). They ride inside `metadata:` rather
than at the front matter's top level for the same reason the rest of this block does: it is the
namespace every harness's parser already ignores.
