# Operator inspects working-tree diff

This journey covers the as-built operator path through the [groom dashboard](../gui/screens/groom-dashboard.md) for inspecting one workflow checkout's working-tree changes. It can start from the selected run's [working-tree diff disclosure](../gui/screens/groom-dashboard.md#detail-working-tree-diff-toggle), which fetches the default checkout diff directly into the detail pane, or from the dashboard Diff activity mode, which uses the shared repository picker to choose a container/repository, loads [workspace diff data](../workspace-diff-data.md) through [GET /diff/{container_id}](../http/groom.md#get-working-tree-diff), renders a changed-file tree through the [dashboard path tree](../dashboard-path-tree.md), and renders one chosen parsed file through Diff2Html. Server-side diff reads prefer [sidecar live sessions](../sidecar-live-sessions.md) `getDiff` RPCs and fall back to the workflow workspace-volume diff reader when no live sidecar can serve the data.

The wire carries the raw unified diff as one JSON string — `{"diff": "…"}` — and nothing else. Diff2Html both parses that text and renders it, and it escapes what it emits, which is why the diff rides through unsplit rather than having half a parser reimplemented server-side. Parsing and rendering happen in the browser, once per load; selecting a file afterwards costs no request.

- start: the groom server is running, the browser has loaded the [groom dashboard](../gui/screens/groom-dashboard.md), and at least one [workflow container](../concepts/workflow-container.md) may have a known `workspace_volume`. For the detail-disclosure path, a run is selected in the Runs pane detail. For the Diff pane path, the dashboard may start with no selected repository, or with [dashboard selected repository state](../dashboard-selected-repository-state.md) already populated from an earlier Files or Diff pane selection.
- steps:
  1. Optional detail entry: the operator expands [toggle detail working tree diff](../gui/screens/groom-dashboard.md#toggle-detail-working-tree-diff) from the selected run's detail pane. The disclosure is a component with its own local loaded/failed state rather than wiring re-attached after each push — it ignores closing events and an already-loaded body, shows `Loading diff…` on first expansion, and sends `GET /diff/{container_id}` without a `repo` query so the endpoint uses its default checkout selection. Because that state is component-local and the pane is keyed, a detail push arriving mid-read neither re-fetches the diff nor collapses the disclosure.
  2. [Serve workspace diff](../http/groom.md#serve-working-tree-diff) handles the detail-disclosure request or any later Diff pane request. It first asks the connected sidecar, when present, for `getDiff` with the selected `repo` value, returns the successful RPC result's `diff` member, and otherwise falls back to the workflow's known workspace volume through the [workspace volume diff reader](../concepts/workspace-volume-diff-reader.md). Unknown workflow state, missing volume metadata, sidecar RPC failure, falsey sidecar diff, no checkout, git failure, timeout, or empty working tree all become `200 OK` with an empty `diff` string rather than an endpoint-specific error body.
  3. For the detail-disclosure path, the browser reads the fulfilled response as JSON and takes `diff`, defaulting an absent value to the empty string. Whitespace-only text renders `(no changes)`; non-whitespace text is handed to Diff2Html with `drawFileList: true`, line matching, line-by-line output, and dark colour scheme, and its escaped output is set as markup. A fetch or body-read rejection writes `failed to load diff` and leaves the disclosure retryable on the next open. This path ends inside the detail pane and selects neither a repository nor a changed-file row.
  4. Primary Diff pane entry: the operator activates [select activity diff mode](../gui/screens/groom-dashboard.md#select-activity-diff-mode) from the activity bar. The dashboard sets `.app[data-mode]` to `diff`, marks the Diff activity control active and `aria-pressed="true"`, writes the mode into the [dashboard client store](../concepts/dashboard-client-store.md), closes the shared repository menu if it was open, and enters the Diff pane load path.
  5. If no repository container is selected, the Diff pane load path returns without a request and the tree island renders `Pick a container / repo above.` from store state alone, leaving the diff viewer on its empty prompt. If a repository is already selected, the load path resets the diff slice to `loading` with no parsed files and no selected index — which renders `Loading changes…` in the tree and `Select a changed file to see its diff.` in the viewer — and sends `GET /diff/{container_id}?repo={repo}`.
  6. When a repository must be chosen, the operator activates [open diff repository picker](../gui/screens/groom-dashboard.md#open-diff-repository-picker). The browser positions and opens the shared repository menu against the invoking button, sets `aria-expanded="true"` on the [repository menu search input](../gui/screens/groom-dashboard.md#repository-menu-search-input), clears and focuses it, sets the repo slice to `loading` — rendering `Loading…` in the menu — and fetches [GET /repos](../http/groom.md#get-repository-menu).
  7. [Serve repository menu](../http/groom.md#serve-repository-menu) reads the current in-memory workflow registry, keeps workflows with known workspace volumes, resolves checkout directories through the [workspace volume repository-directory reader](../concepts/workspace-volume-repository-directory-reader.md), and returns [repository menu data](../repository-menu-data.md) as JSON groups. Individual checkout-discovery failures become root options or absent entries for that workflow rather than a failed menu endpoint response.
  8. The dashboard stores the returned groups, and the menu island renders one [repository menu option](../gui/screens/groom-dashboard.md#repository-menu-option) per container/checkout pair. The operator may use [filter repository menu options](../gui/screens/groom-dashboard.md#filter-repository-menu-options), which re-derives the visible rows from the stored groups by case-insensitive label matching without requesting new data, selecting an option, or changing the active pane.
  9. The operator activates [select repository menu option](../gui/screens/groom-dashboard.md#select-repository-menu-option). The dashboard stores the option's container, checkout directory, and label in [dashboard selected repository state](../dashboard-selected-repository-state.md), writes that label into every repository picker button, dispatches the [dashboard active pane loader](../concepts/dashboard-active-pane-loader.md), and closes the menu with focus returned to the invoking button.
  10. Because the active mode is `diff`, the active-pane loader follows the Diff pane load path: it resets the diff slice to `loading` with no parsed files and no selected index, and sends `GET /diff/{container_id}?repo={repo}` to [get workspace diff](../http/groom.md#get-working-tree-diff) with the selected container id and checkout path URL-encoded from store state.
  11. The browser reads the fulfilled response as JSON and takes `diff` as [workspace diff data](../workspace-diff-data.md). Whitespace-only text — and a `Diff2Html` that failed to load — yields an empty parsed-file array, which the tree renders as `(no changes)`; fetch rejection or body-read rejection marks the slice `error`, which renders `failed to load`. Both paths leave the diff viewer on its empty selected-file prompt, because no file index is selected.
  12. When the body contains non-whitespace unified diff text, the loader parses it once with the third-party Diff2Html parser and stores the resulting array in the diff slice as the [dashboard parsed diff file cache](../dashboard-parsed-diff-file-cache.md). A zero-file parse is indistinguishable from empty diff text and renders `(no changes)`.
  13. The tree island derives one entry per parsed file: the path is `newName` unless it is missing or `/dev/null`, in which case `oldName`; it also carries the file's original index in the parsed array plus its added- and deleted-line counts. Those entries go through the [dashboard tree builder](../concepts/dashboard-tree-builder.md), the same flat-paths-to-nested-nodes function the Files pane uses, producing one [dashboard path tree](../dashboard-path-tree.md).
  14. The island renders [diff directory toggle](../gui/screens/groom-dashboard.md#diff-directory-toggle) rows for directory nodes and [diff file row](../gui/screens/groom-dashboard.md#diff-file-row) leaves for changed files, directories before files, directory keys sorted, and sibling leaves sorted by displayed basename with `localeCompare`. Names are rendered as text nodes, so no escaping step stands between the parsed diff and the document. Each leaf shows its added and deleted counts and is keyed by its parsed-file index.
  15. The operator may activate [toggle diff directory](../gui/screens/groom-dashboard.md#toggle-diff-directory). Collapse state is component-local to that directory node and survives re-render because the node is keyed by name; toggling flips the row's `aria-expanded` and its subtree's visibility without fetching data, reparsing the diff, selecting a file, or changing repository state.
  16. The operator activates [select diff file row](../gui/screens/groom-dashboard.md#select-diff-file-row). The dashboard writes that leaf's parsed-file index into the diff slice — one store write, which is what marks that row and only that row `active`/`aria-current="true"`, since every row's selected state is derived from the same index.
  17. The diff viewer reads the parsed file at the selected index straight out of the cache and renders it with Diff2Html for a one-element array, using `drawFileList: false`, line matching, line-by-line output, and dark colour scheme. Selecting a file sends no HTTP request, reparses no raw diff text, mutates no server state, changes no URL, and sends no websocket message.
- end: the dashboard remains in Diff mode with the selected repository label visible on both repository picker buttons, the diff tree built from the latest parsed-file cache, directory collapse state held per component, at most one changed-file row marked `active`/`aria-current`, and the diff viewer showing either the selected file's dark line-by-line Diff2Html render, the empty selected-file prompt, `(no changes)` in the tree, or `failed to load` after a client-side fetch or body-read failure. Server-side sidecar and fallback diff failures are represented as an empty `diff` string, not endpoint-specific error responses.
