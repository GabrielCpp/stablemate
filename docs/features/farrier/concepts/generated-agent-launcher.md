# Generated agent launcher

The repository-scope renderer always produces [`.agents/agents.mk`](../farrier.md#install) as a
tracked, byte-identical launcher. It is the make entry point for regenerating and checking
Farrier's adapters and, when requested, for running an installed workflow in an isolated
container. The launcher is generated from the [renderer](renderer.md), while the set of runnable
workflows is resolved from the machine at make parse time rather than recorded in the file.

The launcher module's public path constants identify the generated repository artifacts: the
generic context manifest is `.agents/agents-context.json`, assistant-specific manifests use
`.agents/agents-context.<assistant>.json`, and the optional thin root entrypoint is `Makefile`.
`.agents/local.compose.yaml` remains a convention-owned cleanup path for installations from the
retired Compose-override design; current rendering does not produce it.

`agents.yml` does not select workflows for this launcher. A workflow is an installed Python
distribution with its own `workhorse-<name>` command; `agents.mk` asks `farrier workflows --names`
only when a goal matching `agent-run-%` is requested and turns each returned name into a real make
target. An unknown name therefore fails with make's own `No rule to make target` error, and
unrelated make goals do not pay the discovery cost.

Each generated run mints a UUID on the host and uses it in the Compose project name, the
git-worktree root under `.agents/worktrees/<uuid>`, and the explicit `AGENT_RUN_ID`. It passes the
repository path, repository basename, base branch, worktree path, selected profile, and staged
configuration into the container. The run uses the stablemate checkout's
`workhorse/compose.yaml`, runs with uid `65534` and the operator's group by default, and sets the
source repository's local `core.sharedRepository=group` only when that setting is absent so
container-written work remains usable from the host.

When present, the operator's Claude credentials are copied per run with mode `640`; a missing
credentials file is allowed because an OAuth-token environment path can authenticate the
container. A named profile snapshots the selected config into the run directory and fails when an
explicit config is unreadable or when no config exists behind the profile. Without a profile, the
container receives an empty profile name and resolves its normal top-level configuration.

The stable launcher targets are `agent-help`, `agent-install`, `agent-check`,
`farrier-run-hook`, `agent-workflows`, `agent-runs`, `agent-logs`, `agent-stop`, and `agent-clean`.
The run-operation targets require `RUN=<workflow>-<uuid>`; stop preserves volumes so a Docker
restart can resume the same run, while clean removes the container and its per-run volumes.
`agent-install` regenerates adapters and `agent-check` performs the no-write drift check. The
launcher claims the default goal only when it is the only makefile in play and never overrides an
including repository's `help` target.

`.agents/local.compose.yaml` is not generated by the current renderer. Its path remains a
convention-owned cleanup target solely so an older install's per-workflow Compose override can be
removed; current expected-output and extra-file scans do not inspect it. This is the compatibility
boundary between the retired YAML-era launcher and the current installed-workflow launcher.

## Methods

### remove_targets
- sig: `remove_targets(repo: Path, managed: Managed = REPO_MANAGED) -> None`
- does: sweep each configured managed directory and delete only files classified as Farrier-owned
- does: delete each existing Farrier-owned file named by the managed-file list
- does: delete each regular file matching an assumed-owned path pattern, including the legacy
  `.agents/local.compose.yaml`, without requiring an ownership marker
- does: leave non-file matches for assumed-owned patterns unchanged
- returns: `None` after the configured cleanup passes complete
- verify: removed(subject="legacy .agents/local.compose.yaml")
- verify: unchanged(subject="untagged file during output cleanup")
- code: `farrier/farrier/outputs.py::remove_targets`
