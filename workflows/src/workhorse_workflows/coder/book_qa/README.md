# book_qa

The book lane of the coder workflow. A story that touches a service with an executable book (`services/<name>/service.py` under the book root: the repo root in a monorepo, the artifacts folder in a multi-repo workspace) has that service judged by a run of the book. The scenario QA in `qa/` is a separate lane, and the main loop hands off to this one first. Both return a `QaFlowResult`.

The lane costs one seat turn. The verdict costs no model call. A story with no covered service ends here as `passed` with no agent call and no stack.

## How a story's book pass settles

1. `start` lists the story's covered services: the declared ones that have a book, then every other service with a book whose app source the story's commits changed (`ostler book stale --since <story base>`, the story base being the commit its own work started from). It then leases a copy of the stack and brings it up. A stack that is not up goes to the operator, never to the seat. A `book-qa.json` in the spec dir holds the calls the plans selected, so a second visit for the same story goes straight to `check`.
2. `work` runs the `qa-book` seat. It brings each covered book up to the story's claims and reports a finding for each claim the app does not meet. A `blocked` reply asks the operator.
3. `check` runs `ostler book check` for each covered service. It then runs `ostler book affected` for the service, with the story base as `--since` and, when a commit reachable from HEAD carries the trailer `Story: <id>`, with `--story <id>` so that only the story's own commits and the uncommitted work are read (the lane logs `the selection of <service> reads the N commit(s) of story <id>`, or `no commit carries 'Story: <id>'` and reads the range since the base), which selects the plays from the diff of the app's code and of the book's own files, with no app and no model call. Exit 2 of the selection, or a changed file or function no element of the book names, goes back to the seat, and nothing is played until it is fixed. A plan of `none` or `empty` plays nothing for that service. A plan of `partial` plays `ostler book run --only <calls>` and then, when the plan names journeys, `--partial --journey <title>`, as two plays because the two flags combine as AND. A plan of `whole`, or a pass that changed a shared part of the book, never plays the whole book: the service plays the calls and journeys the selection still names, and the reason the selection could not narrow is listed as owed to a scheduled whole play, which runs outside any story. Before each play the lane logs what it will play and its limit. Every play reloads the data first (`--fresh-data` on the first play of a service), runs against `--copy <lease>` and ends within `book_play_minutes` minutes (15 by default, a workflow parameter of the coder), or exits 3. Exit 1 or 2 of a play goes back to the seat with the tail of the output. Exit 3 means the environment could not be judged, and it asks the operator without a finding or a lap. When no service plays anything and one has an owed entry, the seat gets a lap that lists the owed reasons: the change could not be narrowed to any play, so state it in an element a play reaches. When no service plays anything, none is owed and the story changed files, the seat gets a lap: the book does not state what the story changed. A story that changed nothing passes with no play. Each pass of `check` writes `qa-plan.md` in the spec dir from code: the plan, the change read (`- change read:`, the story's commits or the range), its reason, the calls, the journeys, the uncovered list, the changed and unjudged file counts and the exit of each play, a line per service of what is owed to the scheduled whole play (the first 10 reasons, then `and N more`), and a top line saying whole plays are never run for a story. The reports of the plays land under `qa/book` in the spec dir.
4. Exit 0 on every service with no finding runs `ostler book verified` for each covered service whose book was current when the story started, so the book records the app commit it was judged at. The stale report against the book's verified commit must name only entries the report since the story's base also names. A book already current, a book with no verified commit and a book that was behind before the story are left alone and sent no lap, so a second visit stamps nothing twice and the catch-up flow keeps the older changes in view. A refusal goes back to the seat with the output. Then the lane lands the changed paths under each covered `services/<name>/` as one `test` commit with the story's footer, and writes `book-qa.json`. A changed product path outside those folders refuses the commit and goes back to the seat. The lane ends as `refix` with the seat's findings, or as `passed`. A finding stops the story even on a green run, because a declared defect makes the run green by design.

Checks that still fail after three repair turns park the run at the operator gate.
