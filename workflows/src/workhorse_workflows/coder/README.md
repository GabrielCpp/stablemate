# coder

The `coder` workflow turns epics and stories into committed code. The launch packs the stories into the run's worklist: every epic the project's milestones list (`epic=all`, the default), one epic (`epic=<name>`), or one story (`story=<slug>`). With `epic=all` the epics come in milestone order: a milestone's `dependsOn` milestones first, then its `epics:` list in order, and a superseded milestone gives none. A launch over every epic fails before any turn when no milestone lists an epic or a milestone lists one the book does not hold. The worklist belongs to the run. The run never writes the milestones and keeps no shared queue. Each lane is its own state machine, and the main loop runs them over the worklist in order.

The `delivery` parameter decides where the work lands. With `pr`, the default, every item commits on one `feat/` branch, and the run opens one PR per repo it changed, waits for its CI to go green and leaves the merge to a reviewer. With `commit`, every item commits on the branch each repo is on, and no PR opens. In both, each story's commits carry its `Story:` footer.
