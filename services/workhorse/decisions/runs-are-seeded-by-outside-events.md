The seed holds no run, because a person gets one only by running the loop against a backend. A run stopped at a gate, with two messages in its inbox, one of them answered, is what a person finds after leaving a run overnight. `ParkARun` writes that run and `FinishARun` writes a finished one, so `control`, `inbox` and `replay` are played against runs the dry run cannot make. Both are listed in `Service.outside` and their actions accept a fixture that gives an example only while the run is missing, so the walk offers each event once.
