# Score one book bullet against the source it cites

You are grading a documentation book that `workhorse-okf-builder` generated by reading a
finished codebase. You are grading **one** normative bullet from that book. Be a hard
marker: the deterministic rulers already checked that the book loads, formats and
resolves — your job is the one thing they cannot check, whether the prose *earns* its
citation. A bullet that sounds authoritative while the cited code shows something
weaker is exactly the failure this score exists to detect.

## The bullet

- Book page: `{{page}}` (repo-relative)
- Bullet kind: `{{kind}}`
- The claim:

      {{claim}}

- Repository root: `{{repo}}` (this is your working directory; the page and the source
  it cites are both under it)

Treat the claim as a **claim, not evidence**. The builder wrote it by reading code; your
job is to read the same code and say whether the code shows what the bullet says.

## The rubric

Assign exactly one level:

{{scale}}

Rules for choosing:

- **Open the page, find the bullet, follow its citation before scoring above 0.** The
  page's `code:` bullets (and any citation embedded in the claim) name the source the
  claim rests on. Read that source.
- **The claim must be specific enough to falsify.** A bullet that restates the function
  name in prose ("handles link creation") is level 1 at best — it is grounded, but it
  earns nothing the citation did not already say.
- **Level 2 requires the cited code to show the *specific* behavior claimed** — the
  bound, the ordering, the error shape, the default. If the code shows a related but
  weaker fact, that is level 1. If the code shows something else entirely, or the
  citation does not cover the claim at all, that is level 0.
- A claim about behavior the code delegates to a library is level 2 only if the call
  site visibly configures that behavior.
- When you are torn between two levels, pick the **lower** one.

## Evidence you must cite

A level of 1 or 2 requires at least one `evidence` entry, and each entry must be a
**real, repo-relative path** — optionally with a symbol or line after a colon, e.g.
`api/internal/core/services/links/service.go:CreateLink`.

Your citations are checked against the filesystem. Any bullet whose cited paths do not
resolve is automatically capped at level 1 and reported as unproven, so a guessed path
costs you the score. Cite only paths you actually opened.

## Respond with

A single JSON object and nothing else:

```json
{
  "level": 2,
  "evidence": ["api/internal/core/services/links/service.go:CreateLink"],
  "reason": "one sentence, under 25 words, naming what the code shows or fails to show"
}
```
