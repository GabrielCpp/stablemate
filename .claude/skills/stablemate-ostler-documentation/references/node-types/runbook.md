# `runbook`

How a stack is brought up, kept up, and torn down: the durable-stack contract a QA session
runs against. Reach for `runbook` when the subject is *operating* the system rather than using
it. Its ordered boot steps are [`step`](step.md) nodes under `## Steps`.

A runbook supersedes the fallback launch contract on a [`server`](server.md) node. It boots an
[`environment`](environment.md).

## Identity

File type under `docs/features/<service>/ops/`, `type: runbook` in frontmatter.

## Bullet keys

| key | required | what it does |
| --- | --- | --- |
| `driver` | **yes** | `web` \| `mobile` \| `http` \| `cli` \| `artifact` \| `iac` \| `none` |
| `environment` | no | link — the environment this boots (default local) |
| `cli` | no | link — the dev-CLI node it drives with |
| `surfaces` | no | link — the screen/server/cli/format nodes it exposes |
| `code` | no | link, **owns** its file — the launch entry point |
| `entry-url` | no | base of the HTTP readiness probe |
| `health-path` | no | joined onto `entry-url` (default `/`) |
| `identity` | no | substring of the health **body** proving the stack is ours |
| `reuse` | no | `if-fresh` (default) \| `always` \| `never` |
| `fresh` | no | a command exiting 0 iff a serving stack reflects current code |
| `boot-timeout` | no | seconds; ceiling on bring-up |
| `health-timeout` | no | seconds; one window shared by all health gates |
| `stop` | no | teardown recipe; absent means leave it running |
| `working-directory` | no | cwd for the launch and every step not overriding it |
| `secrets` | no | nested; `NAME: <shell that prints the secret>`, one child each |

These scalars are read by `ostler.qa.runbook`, which folds them plus the `## Steps` sections
into the manifest `ensure_stack` takes. They are scalars because the steps carry everything
ordered.

`secrets:` are minted per QA **run**, not per bring-up: a short-lived token issued while the
stack booted is already stale by the lap that spends it, and a secret may never be
checkpointed — so the value is a command that prints it, never the secret.

Plus the [shared normative keys](../bullet-grammar.md#keys-that-are-normative-on-every-type).

## Required sections

`## Steps` — required and required to be non-empty, and exactly one step must be
`kind: service`. A runbook brings up one stack; everything else is `kind: prepare`.

## Relationships

`environment:`, `cli:` and `surfaces:` all resolve as links. A runbook is what ties the
operational nodes to the product surfaces.

## Minimal example

```bash
timeout 30 ostler scaffold runbook links-local --service acme
```

```markdown
---
type: runbook
---

# Links (local)

- driver: http
- environment: [local](environment-local.md)
- surfaces: [links-api](../http/links-api.md)
- entry-url: http://127.0.0.1:8080
- health-path: /healthz
- identity: links-api
- reuse: if-fresh
- stop: docker compose down

## Steps

### migrate

- kind: prepare
- run: make migrate
- timeout: 60

### serve

- kind: service
- run: make serve
- health: GET /healthz returns 200 with "links-api" in the body
```

## Doctor codes it can trip

`runbook-missing` (warn, raised when no runbook exists at all), `runbook-bad-reuse`,
`runbook-bad-kind`, `runbook-incomplete`, `runbook-multi-service`, `runbook-local-only`,
`missing-required-bullet` on `driver:`, `missing-required-section`,
`empty-required-section`. See [../doctor-codes.md](../doctor-codes.md).

## When bullets are not enough

The contract states how this stack comes up. If a reader could pick the wrong runbook — a
legacy bring-up and its replacement, each right in its own context — and still satisfy every
claim on it, that belongs in a [`concept`](concept.md), pointed at with `detail:`.
